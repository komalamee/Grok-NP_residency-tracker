# Nomad Pro v2: changes, 28 Sep 2026 (drafts only)

These are drafts only. Nothing was published or pushed to the live agent, and no one was messaged. The shared skills in `/home/box/agent-data/workflows/` and the engine are untouched. `skills.diff` has been regenerated (live → draft).

## What changed
1. **Three routines are on by default** (Koko approved): the daily check-in at 21:00, the HMRC guidance watch on Wednesdays at 09:00 (with the engine update check) and the travel-rules watch on Mondays at 09:00. They start in the user's timezone right after the first count. The monthly backup stays off and is offered once there are 30+ days of logs. The 7 April year-end lockdown is unchanged from the previous draft: it's offered once 30+ days are logged, not on by default. The calendar review still runs only if the calendar is connected. This is updated in getting-started, onboarding, check-in, both watches, backup, year-end, core rules, the listing and PACKAGING.md.
2. **The check-in is now one tap.** It asks one question, for example "Still in Bangkok today?", guessed from the last night logged or from the calendar. A "yes" gets "Logged: Bangkok, 28 Sep." The work question comes only on a UK day the work rule doesn't settle. "skip" or no reply logs nothing and sends nothing more. There are no reminders, no messages between 22:00 and 08:00, and "stop", "pause" and "change time" all work.
3. **The watches stay silent unless something changes.** Nothing is sent on the first run after install, for date-only HMRC updates or when a fetch fails, and there are never "no changes" messages. When something does change, the message is at most 3 lines.
4. **Sunday "where you stand" line.** One visual line goes in Sunday's check-in: `UK ▓▓▓░░░░░░░ 5/16 · Schengen ▓▓▓▓▓▓▓▓▓░ 77/90 · 0 missing`.
5. **Heads-up before a line.** When a UK figure, the ties-test line, next year's 90-day tie, UK work days, Schengen or another stay limit moves into "getting close", "at the line" or "over the line", the bot sends one bar plus one line, once per band. It gives counts and dates only and never suggests what to do.
6. **Missed days are caught up in one tap.** For example: "Missed 3 days (25–27 Sep). Bangkok all 3?" The bot writes those rows only after a yes, so gaps are still never guessed.
7. **Trip "what if" before booking.** The reply shows the count now and with the trip as two bars, plus at most 2 lines, then asks "Save this trip? I'll recheck it weekly." Saved trips feed the heads-ups.
8. **One-step file for your accountant.** "File for my accountant" produces the PDF and CSV with a one-line count summary, plus a cover note the user can paste and send themselves. The bot never sends it.
9. **Guardrail wording.** The 183 line no longer uses "safe". It now reads "183 UK days is the figure for the first automatic UK test. Being under it doesn't settle anything on its own." Added "verdict", "determine(s)" and "the answer" to the words the bot never uses. The first-run message now says the check-in is on instead of asking. The routine rule is now in core rules: at most one message per run.
10. **Listing (v2c).** Adds the one-tap check-in, the Sunday line, heads-ups, "what if" and "files for your accountant", plus a new "On from day one" line and 4 example prompts. The copy is about 215 words (194 before). profile.json is unchanged.

## Travel log Sheet as the single source (28 Sep 2026, drafts only, not live)
- **Six tabs:** Summary (Item · Value · Source rows · As of), Days (adds Row ID `D-YYYY-MM-DD`; A–K), Records (Record ID · Proves days · Type · Description · File or link), Trips (Trip ID · Country · Place · First night · Last night · Status · Result when saved · Saved on · Last checked), Changes (Day changed · Field · From · To · Via · Reason · Changed at), Outputs (Output ID · Date · Type · Date range · Rows used · File location).
- **The Sheet is the source.** The bot writes changes to the Sheet first; before every count, check-in, output or routine run it rebuilds `daylog.json` from the Sheet after `validate`. The Sheet wins; an invalid row keeps its last valid value and is flagged in one line. Profile answers (prior years, ties, work-day rules, passports) stay in `daylog.json`; they aren't in the six tabs.
- **Traceability.** Every PDF, CSV, dashboard, accountant file, records pack, backup and year-end file gets an Outputs row and "Source: Nomad Pro – Travel log, rows <first>–<last>, generated <date>". Chat counts name their source rows when asked (Summary → Source rows).
- **Tidy-ups:** plain labels mapped back when read ("Portugal (PT)", "You told me", "Daily check-in", "Idea (what if)"); row 1 one-line note, shaded blue editable headers, grey log-only headers; "Also in (travel day)"; blank instead of n/a; "Day changed" / "Changed at".
